Выполнены следующие задачи:
Блок Б: Состояние и доступ, сессии, cookie, подпись, кэш.
    1. Б1 - Сессия: «недавно просмотренные отели»
        
        1.1 Файл hotels/views.py: Изменены фуеция hotel_detail() и класс HotelListView, добавлено сохранение 5 последних просмотров. Список последних пяти просмотренных отелей в виде якорных ссылок внедрен в шаблон страницы каталога отлелей hotels/list.html ниже формы поиска отелей. Также добавлен соответствующий класс в base.css

        1.2 В файл hotels/tests.py добавлен класс RecentHotelViewsTests. Проверяются условия:
            1) При первом просмотре ID отеля появляется в сессии.
            2) Новый отель добавляется в начало списка.
            3) Повторный просмотр не создаёт дубликат, а перемещает отель в начало.
            4) Сохраняются максимум пять последних отелей.
            5) Неактивный или несуществующий отель не попадает в историю.
    
    2. Б.2 - Подписанная cookie

        1.1 Файл hotels/views.py: изменен класс HotelListView, реализовано:
            1) Сохранение города в подписанной cookie.
            2) Восстановление города при повторном посещении.
            3) Приоритет нового значения city из GET-параметров.
            4) Удаление сохранённого города при пустом поиске.
            5) Игнорирование cookie с некорректной подписью.
            
        1.2 В файл hotels/tests.py добавлен класс HotelCityCookieTests. Проверяются условия:
            1) Город сохраняется в подписанную cookie на 30 дней.
            2) Без GET-параметра город восстанавливается из cookie.
            3) Новый город в GET-параметре имеет приоритет над cookie.
            4) Явный пустой поиск удаляет сохранённый город.
            5) Cookie с неправильной подписью игнорируется.
    
    3. Б.3 - Подписывание данных: ссылка-ваучер брони
        1.1 Добавлены файлы bookings/voucher.py, шаблон bookings/voucher.html, в файл bookings/view.py добавлена функция booking_voucher(), в маршрутах bookings/urls/py добавлен новый маршрут на страницу ваучера.
        Реализовано:
            1) Формирование токена для подтверждённого бронирования.
            2) Добавлен публичный маршрут /bookings/voucher/<token>/, который не требует входа в аккаунт.
            3) Проверка подписи и срока действия токена. Срок действия — 7 дней.
            4) Показ ваучера, если ссылка действительна и бронь подтверждена.
            5) Возвращается HTTP 404, если токен подделан, просрочен, некорректен либо относится к бронированию, которое не должно выдавать ваучер.
        1.2 В файл bookings/tests.py добавлен класс BookingVoucherTests. Условия тестов для Б.3:
            1) Действительная ссылка открывает ваучер без авторизации — HTTP 200.+
            2) Поддельный токен возвращает HTTP 404.
            3) Просроченный токен возвращает HTTP 404.
            4) Для бронирования со статусом pending ваучер недоступен — HTTP 404.
            5) Для подтверждённого бронирования ссылка действительно содержит подписанный токен.
